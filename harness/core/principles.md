# 하네스 원칙

## 저장소 분리

개인 하네스는 대상 프로젝트의 일부가 아니라 overlay로 다룬다. 공유 프로젝트
지침을 먼저 읽고, 개인 메모는 그 규칙을 약화하지 않는 범위에서만 적용한다.

## 우선순위

1. 사용자의 최신 요청.
2. 대상 저장소의 `AGENTS.md`, `CLAUDE.md`, 하위 영역 규칙.
3. `harness/projects/<project>/`의 개인 프로젝트 overlay.
4. `harness/core/`의 재사용 규칙.

규칙이 충돌하면 더 구체적이고 안전한 규칙을 따른다. 개인 선호를 이유로 공유
프로젝트의 안전, 검증, 커밋 규칙을 약화하지 않는다.

## 언어

새 하네스 문서와 개인 메모리는 기본적으로 한국어로 작성한다. 코드, 명령어,
파일 경로, 환경 변수, API 이름은 원문을 유지한다.

## Private Overlay

private overlay에는 다음을 기록한다.

- 개인 메모와 선호
- 구조화 질문 답변 중 오래 유지될 선호
- 반복되는 이슈
- 공유 저장소에 넣기에는 시끄럽거나 부적절한 메모
- 반복 근거가 더 필요한 규칙 후보

비밀값, credential, private key, token, license 데이터는 저장하지 않는다.

## 규칙 승격

규칙은 다음 조건을 만족할 때만 승격한다.

- 반복되었거나 영향이 명확히 크다.
- 다른 에이전트가 실행할 수 있을 만큼 객관적이다.
- 팀이나 미래 유지보수자에게 유익하다.
- 단순한 개인 문체 취향이 아니다.

주관적 선호는 overlay에 남긴다.

## 질문

사용자 판단이 필요하면 `ask-user-question.md`를 따른다. 런타임이 구조화 질문
도구를 지원하면 그것을 우선 사용하고, 지원하지 않으면 짧은 일반 질문 하나로
대체한다.
