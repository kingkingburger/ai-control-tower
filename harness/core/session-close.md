# 세션 종료 워크플로

사용자가 세션 종료, 마무리, closing, wrap-up을 요청하면 이 흐름을 사용한다.

## 단계

1. 대상 저장소 상태를 확인한다.
2. 변경 파일을 검토하고 무관한 사용자 변경은 제외한다.
3. 변경에 맞는 집중 검증을 실행한다.
4. 세션 종료에 커밋이 포함된다는 사용자 기대가 있으면 관련 대상 저장소 변경을
   커밋한다.
5. 명시적으로 요청하지 않으면 push하지 않는다.
6. `closing-lite`를 실행하거나 동일한 경량 메모리 축적을 수행한다.
7. 배운 점을 이 하네스의 대상 프로젝트 private overlay에 추가한다.
8. 나중에 공유 문서로 승격할 후보 규칙을 식별한다.

이 메모리 단계는 매 세션 종료마다 필수다. 배운 점과 하네스에 증강할 점을 함께
기록한다.

## Closing-Lite 메모리 형식

짧은 항목으로 다음을 기록한다.

- 날짜
- 대상 저장소
- 완료한 작업
- 검증
- 배운 선호 또는 반복 이슈
- 후보 규칙
- 하네스 증강 아이디어

짧게 유지한다. 목표는 전체 transcript가 아니라 복리로 쌓이는 메모리다.
기본적으로 한국어로 작성한다.

## 사용자에게 직접 공유

세션 종료 요약은 파일에만 남기지 않는다. 사용자에게 이번 세션에서 배운 점, 다음에
조심할 점, 확인된 사용자 선호, 하네스나 프로젝트 지침에 반영한 내용을 직접 짧게
알려준다.

## 메모리 위치

프로젝트별 히스토리와 학습은 해당 프로젝트 안의 명시된 메모리 문서에 누적한다.
특정 도구의 `.omc/project-memory.json` 같은 상태 파일은 지속 메모리 원본으로 쓰지
않는다. 여러 프로젝트에 반복 적용할 운영 규칙만 `ai-control-tower/harness/core`로
승격한다.
