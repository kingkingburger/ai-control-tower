# 사용자 질문 정책

로컬 맥락만으로 안전하게 판단할 수 없는 결정이 있으면 사용자에게 질문한다.

## 질문해야 하는 경우

다음 상황에서는 진행 전에 묻는다.

- 선택이 아키텍처, 공개 동작, 데이터 형태, 커밋 범위를 바꾼다.
- 사용자 선호가 중요한 산출물인데 기존 선호가 없다.
- 여러 유효한 선택지의 tradeoff가 의미 있게 다르다.
- 공유 저장소에 개인 맥락이 섞일 수 있다.
- 파일, 테스트, 기존 지침에서 답을 찾을 수 없다.

저장소에서 합리적으로 추론할 수 있는 낮은 위험의 세부사항은 묻지 않는다.

## 선호 형식

런타임이 `AskUserQuestion` 또는 동등한 구조화 질문 도구를 제공하면 다음 형태로
사용한다.

- 짧은 질문 1-3개
- 서로 배타적인 선택지 2-3개
- 추천 선택지를 첫 번째에 배치
- tradeoff 설명은 간결하게 작성

구조화 질문을 사용할 수 없으면 짧은 일반 질문 하나를 하고, 사용자가 답한 뒤
계속 진행한다.

## 좋은 질문 기준

좋은 질문은 다음 조건을 만족한다.

- 어떤 결정을 하는지 명확히 말한다.
- 영향도를 한 문장으로 설명한다.
- 사용자가 요청하지 않은 개방형 브레인스토밍을 피한다.
- 저장소에 이미 있는 정보를 다시 묻지 않는다.

## 메모리

사용자 답변이 오래 유지될 선호를 드러내면 세션 종료 때 프로젝트 overlay의
`session-memory.md`에 기록한다. 반복되는 선호는 `agent-rules-candidates.md`로
승격한다.
