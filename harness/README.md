# 개인 하네스

이 디렉터리는 개인 AI 엔지니어링 하네스의 원본 저장소다. 공유 프로젝트
저장소와 섞이지 않게 유지한다.

## 목적

- 재사용 가능한 에이전트 규칙, 템플릿, 워크플로를 한곳에 둔다.
- 프로젝트별 private overlay를 유지하되 팀이 보는 저장소를 오염시키지 않는다.
- `closing-lite` 흐름으로 세션에서 배운 점을 누적하고, 안정적이고 공유 가능한
  규칙만 프로젝트 문서로 승격한다.

## 구조

- `core/`: 재사용 가능한 하네스 규칙과 운영 정책.
- `templates/`: 프로젝트 문서 템플릿.
- `projects/`: 특정 저장소용 private overlay.
- `skills/my-harness/`: 이 하네스를 실행하기 위한 Codex 스킬.

## 언어

하네스 문서, private overlay, 세션 메모리, 증강 후보는 기본적으로 한국어로
작성한다. 코드, 명령어, 경로, 환경 변수, API 이름, 외부 고유명사는 원문을
유지한다.

## 경계

공유 저장소에는 팀이 봐도 되는 규칙만 둔다.

- 빌드와 테스트 명령
- 아키텍처와 계층 규칙
- 커밋과 검증 요구사항
- 금지 파일과 안전 경계

이 저장소에는 개인 맥락을 둔다.

- 개인 작업 선호
- 반복되는 에이전트 실수
- 세션 메모리
- 프로젝트 전략 메모
- 아직 팀 문서로 올리기 이른 규칙 후보

## 승격 규칙

1. 1회성 관찰은 프로젝트 `session-memory.md`에 기록한다.
2. 2회 이상 반복되면 `agent-rules-candidates.md`로 올린다.
3. 협업자에게도 유익하면 대상 저장소의 `AGENTS.md`나 docs로 승격한다.
4. 개인 취향이면 이 하네스에만 남긴다.

## 세션 종료 메모리

세션 종료 때마다 관련 프로젝트 overlay에 배운 점과 증강할 점을 반드시
추가한다. 이 누적 메모리가 하네스의 복리 계층이다.

## 프로젝트 메모리와 Core 승격

프로젝트별 히스토리와 학습은 각 프로젝트 안의 명시된 메모리 문서에 누적한다.
`ai-control-tower`는 그 원시 히스토리를 대신 저장하는 곳이 아니라, 반복되는 운영
규칙을 core 규칙, 템플릿, 스킬로 승격하는 곳이다.

`.omc/project-memory.json` 같은 도구 종속 상태 파일은 지속 메모리 원본으로 쓰지
않는다. 유효한 내용은 프로젝트 메모리로 이관하고, 반복 규칙만 이 하네스로
승격한다.
