# [AI Native Camp 2기] Day 4 — 만든 건 초안이다: 멀티 에이전트 실습 + Compound Engineering | 복리의 원리

## 요약

AI Native Camp 2기 마지막 온라인 세션(Day 4, 2026.03.04)으로 총 2시간 26분 분량이다. 장원준이 Compound Engineering 개념과 프레임워크를 설명하고, 정구봉이 멀티 에이전트 세션 랩 실습, 히스토리 분석, 스킬 제작 방법론, 정보 소화 전략을 시연한다. 비개발자 참가자(송일현)의 홈페이지 제작 사례를 Clarify 스킬로 라이브 인터뷰하고, AI 정보 습득 전략과 한국 AI 생태계 경쟁력에 대한 자유 토론으로 마무리한다.

**주요 포인트 3개:**
1. **Compound Engineering = 복리 시스템**: 만들고(Build) → 쓰고(Use) → 불편함 발견(Notice) → 원인 파악(Debug) → 수정(Fix) → 기록(Document) 사이클을 반복하며, CLAUDE.md와 스킬을 계속 다듬어 AI 시스템의 복리 효과를 누린다
2. **멀티 에이전트 세션 랩**: 4개의 서브 에이전트(Document Updater, Automation Scout, Learning Miner, Sustainability Tester)를 병렬 실행하여 세션 결과를 자동 분석·문서화·스킬화하는 컴파운딩 워크플로우
3. **스킬 제작 베스트 프랙티스(Anthropic 가이드)**: 먼저 Claude와 대화하며 작업을 수행한 뒤, 그 과정을 요약하여 스킬로 만들고, 새 세션에서 실행·검증·반복하여 다듬는다

## 인사이트

### 핵심 아이디어

- **Context Engineering → Compound Engineering**: Day 1~3은 맥락(Context)을 AI에게 잘 공급하는 환경 세팅이었고, Day 4는 그 환경을 지속적으로 유지보수·이터레이션하여 복리를 쌓는 방법론
- **AI 시대의 역할 전환**: 지식 노동자 → AI 관리자. 계획 세워주고, 결과 검토하고, 피드백(=Compound Engineering)하는 것이 핵심 루프
- **프롬프트 질 < 환경 세팅**: 예전에는 프롬프트를 잘 쓰는 것이 중요했지만, 이제는 환경(CLAUDE.md, MCP, 스킬)이 잘 세팅되면 프롬프트 하나하나의 질보다 환경 품질이 AI 레버리지를 결정
- **리스크 테이킹**: `--dangerously-skip-permissions` 같은 설정으로 AI에게 더 많은 권한을 주는 것이 시스템 레벨 사고를 가능하게 함. 보수적으로 하기보다 적극적으로 PR/Push 등을 자동화하는 것이 실제로 더 효율적
- **Andrew Ng 데이터**: 워크플로우 설계가 모델 업그레이드보다 2.5배 효과적
- **Harness Engineering**: 모델 성능을 최대로 끌어내는 것은 모델 자체보다 모델을 어떻게 엮어놓느냐(하네스)에 달려 있다

### 적용 가능한 점

- **세션 랩 도입**: 작업 후 자동으로 세션 랩을 돌려 문서 업데이트, 스킬 제안, 학습 포인트를 자동 추출
- **Knowledge 폴더 패턴**: 인사이트를 카테고리별로 분류·저장하고, 3개 이상 유사 인사이트가 쌓이면 패턴 문서로 승격
- **히스토리 인사이트**: `.claude/projects/` 내 JSONL 세션 파일을 분석하여 과거 작업 패턴·인사이트를 추출
- **정보 소화 전략**: X(Twitter)에서 1차 소스 생산자를 팔로우 → FX Embed/Nuzzit으로 아카이빙 → Content Digest 스킬로 퀴즈 기반 학습 → 틀린 부분만 심층 리서치
- **스킬 만드는 법**: (1) Claude와 대화하며 작업 수행 (2) "방금까지 했던 작업을 요약해서 스킬로 만들어줘" (3) 새 세션에서 스킬 실행 (4) 불만족 부분 발견 → 원래 세션으로 돌아가 수정 → 반복

## 상세 내용

### 1. Compound Engineering (장원준)

캠프 전체 흐름 정리:
- **Day 1**: Claude Code 환경 세팅, CLAUDE.md 작성
- **Day 2**: MCP 연결로 다양한 정보 소스 접근
- **Day 3**: Clarify 스킬로 맥락을 구조화·명확화하는 방법
- **Day 4**: 위 환경을 지속적으로 유지보수하며 복리를 쌓는 Compound Engineering

핵심 프레임워크:
```
Build → Use → Notice → Debug → Fix → Document
(만들기 → 사용 → 불편함 발견 → 원인 파악 → 수정 → 기록)
```

Every.to(Dan Shipper)가 주창한 개념으로, AI와 일하는 시스템을 계속 개선하여 복리 효과를 만드는 것. Shopify CEO도 25년부터 모든 의사결정 과정을 MD 파일로 기록하는 방식을 채택.

**실전 수칙:**
- CLAUDE.md를 자기 워크플로우에 맞게 계속 깎아라
- AI에게 적극적으로 권한을 위임하라 (리스크 테이킹)
- 스킬을 인위적으로 만들겠다는 의식을 가져라
- 실수가 발생하면 즉시 시스템에 반영하라 (실수 방지 노트)
- AI한테 기록을 맡기면 AI가 제일 잘 기록한다

### 2. 멀티 에이전트 세션 랩 (정구봉)

세션 랩 = "작업 후 책상 정리 루틴". 작업 세션이 끝난 뒤 자동으로 돌리는 컴파운딩 스킬.

**동작 방식:**
1. **Phase 1 - 변경 내용 확인**: Git diff 등으로 변경 사항 읽기
2. **Phase 2 - 4개 서브 에이전트 병렬 실행**:
   - Document Updater: 문서 업데이트 제안
   - Automation Scout: 새 스킬/자동화 제안
   - Learning Miner: 배울 점 추출
   - Sustainability Tester: 지속 가능성 검증
3. **Phase 3 - 중복 검사**: 에이전트 제안 간 중복(duplicate) 확인
4. **Phase 4 - 액션 선택**: 사용자에게 어떤 작업을 수행할지 질문 (컴파운딩 판단은 사용자가 직접)

서브 에이전트는 Opus가 아닌 경량 모델로 실행 (목적이 명확하고 반복적이므로).

### 3. 히스토리 인사이트 & 세션 애널라이저 (정구봉)

- **히스토리 인사이트**: `.claude/projects/` 폴더 내 JSONL 세션 파일들을 읽어 과거 대화를 분석. Haiku 모델로 배치 처리하여 인사이트 추출.
- **세션 애널라이저**: 특정 세션을 더 깊이 분석. 세션 랩의 Automation Scout 상위 호환. 스킬이 설계대로 동작했는지 빡세게 검증하는 용도.

**사용 패턴:**
- 무지성 첫 실행 → 세션 랩
- 과거 히스토리 돌아보기 → 히스토리 인사이트
- 특정 스킬 동작 검증 → 세션 애널라이저

### 4. 컴파운드 스킬 - Knowledge 폴더 패턴 (장원준)

Auto Memory와 별개로, 더 상세한 인사이트를 축적하는 시스템:

```
knowledge/
├── workflow-patterns/
│   └── multi-agent-parallel-analysis.md
├── problem-solving/
│   └── ...
├── tool-discovery/
│   └── ...
└── design-patterns/
    └── ...
```

- 인사이트 타입(카테고리)을 미리 정의하되, 자기 도메인에 맞게 커스텀
- 세 개 이상 유사 인사이트가 쌓이면 패턴 문서로 승격
- Front matter(태그, 도메인)로 검색 가능하게 구조화
- 카테고리가 모호하면 Claude에게 세션 분석 → 카테고리 제안 → 몇 번 이터레이션

### 5. 스킬 제작 베스트 프랙티스 (정구봉)

Anthropic이 가이드한 방법:
1. Claude와 대화하며 실제 작업을 수행
2. 작업 완료 후 "방금까지 했던 작업을 요약해서 스킬로 만들어줘"
3. 새 세션을 열어 만든 스킬을 바로 실행
4. 의도와 다른 부분 발견 → 원래 세션으로 돌아가 수정 요청
5. 반복하여 스킬을 다듬음

> "완벽한 스킬은 만들 수 없다. 만들고 실행하고 검증하면서 컴파운드 해야 한다."

### 6. AI 정보 습득 전략 (정구봉)

**1차 소스 우선 원칙**: 정보를 직접 생산하는 사람의 X(Twitter)를 팔로우
- Dan Shipper (Every.to)
- Boris (Claude Code 개발자)
- Ryan Carson
- Andrew Ng
- Andrej Karpathy

**소화 워크플로우:**
1. X에서 트윗 수집 → FX Embed로 아카이빙 (직접 크롤링은 X가 차단)
2. Nuzzit 서비스로 RSS 피드처럼 관심 주제별 필터링 (하루 84개 트윗 → 주제별 정리)
3. Content Digest 스킬: 먼저 퀴즈를 풀어보고 → 틀린 부분만 심층 리서치
4. Playwright MCP로 웹 스크래핑 (크롤링 차단된 사이트 우회)

**핵심**: 매일 쏟아지는 AI 소식 중 대부분은 별다른 소식이 아님. 퀴즈로 필터링하여 진짜 모르는 것만 깊이 파고드는 것이 효율적.

### 7. 참가자 PRD 인터뷰 - 송일현 (교육 스타트업)

- 교육 스타트업에서 신사업(대학생 대상 펠로우십 프로그램) 개발 중
- 캠프 참여 목적: 공식 홈페이지 제작 + 참가자용 에이전트/봇 개발
- 레퍼런스 사이트 링크를 첨부하여 Claude Code로 랜딩 페이지 제작
- AskUserQuestion(에스크유저 퀘스천)을 활용해 디테일 조정

정구봉이 라이브로 Clarify 스킬을 시연:
- 모호한 요구사항("캠프를 잘 운영하고 싶다")을 3라운드에 걸쳐 구체화
- 최종 산출물: 운영 방침 문서 + 세션 랩으로 스킬 자동 생성

### 8. 한국 AI 생태계 토론

**정보 소화 프레임워크 (장원준):**
- 신뢰할 수 있는 뉴스레터 중심으로 마켓맵 구축
- 뉴스레터가 많이 인용하는 출처를 2차로 팔로우
- 팟캐스트는 정황/느낌 파악에 최적, 뉴스레터는 밀도·출처 확인에 최적

**한국 AI 경쟁력 (정구봉 + 장원준):**
- 미국(영어권)은 정보 절대량과 디베이트 문화에서 장점
- 한국(서울)은 빠른 실행력과 "뽀모" 문화에서 장점
- oh-my-open-code 사례: 마이너 프로그램의 하네스(harness)임에도 높은 GitHub 스타 수. "More tokens, more intelligence" 철학
- 미국과 1~2일 차이는 있을 수 있지만, 1년씩 앞서는 사람은 논리적으로 없음 → 자신감을 갖고 스텝을 밟을 시기

**AI를 잘 쓰는 사람의 패턴 (정구봉):**
- 특정 페르소나(젊은 세대, 비개발자 등)로 한정되지 않음
- "원래 일을 잘하던 사람들이 AI도 잘 쓴다" — AI 붐이 없었어도 잘했을 사람들
- 언러닝(unlearning)을 잘하는 사람들이 AI 시대에도 빠르게 적응

### 오답 노트

**Q8**: 한국 AI 생태계 토론에서 정구봉이 oh-my-open-code를 예시로 든 핵심 논지는?
- 선택: "한국이 모델 개발에서도 경쟁력 있다" → 정답: "하네스(harness) 레벨에서 한국이 엣지를 가져갈 수 있다"
- oh-my-open-code는 파운데이션 모델이 아니라 마이너 프로그램(OpenClaw)의 하네스(harness)임에도 높은 GitHub 스타 수와 깊은 철학("More tokens, more intelligence")을 보유. 핵심은 한국이 모델 자체가 아닌 모델을 엮어서 쓰는 하네스 레벨에서 충분히 빠르고 엣지를 가져갈 수 있다는 논지.
