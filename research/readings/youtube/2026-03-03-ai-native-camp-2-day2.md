# [AI Native Camp 2기] Day 2 — 업무 도구의 설계 철학부터 MCP 딥다이브, Context Sync 스킬

## 요약

AI Native Camp 2기 Day 2 세션(2026.03.02, 온라인)으로 총 2시간 32분 분량의 강의다. 장원준이 Slack, Gmail, Notion, Airtable, Linear, Google Calendar, Fireflies 등 주요 업무 도구의 설계 철학과 내부 KPI를 분석하여 AI 활용 맥락을 제공하고, 정구봉이 MCP(Model Context Protocol) 개념부터 Notion·Linear·Slack·Gmail MCP 연결 실습, 그리고 Gmail OAuth + Python 스크립트 기반 스킬 플러그인 실습까지 진행한다. 핵심 메시지는 **'맥락(Context)을 AI에게 잘 공급하는 구조를 만드는 것'이 AI 네이티브 업무의 본질**이며, MCP와 스킬을 조합한 Context Sync 패턴이 그 실천 방법이라는 것이다.

**주요 포인트 3개:**
1. 각 업무 도구(Slack, Gmail, Notion, Linear 등)는 고유한 설계 철학과 내부 KPI를 갖고 있으며, 이를 이해하면 AI에게 맥락을 더 정확하게 공급할 수 있다
2. MCP는 빠른 시작용 표준 레이어, 스킬(Python/API 스크립트)은 커스터마이징 레이어 — 실무 최적화는 스킬로 가는 것이 현실적
3. 병렬 에이전트 + 컨텍스트 사전 수집(Context Sync) = AI 생산성의 핵심 패턴

## 인사이트

### 핵심 아이디어

- **AI 네이티브 업무의 본질은 '맥락 공급 구조 설계'** — 똑똑한 AI를 쓰는 것보다 AI에게 올바른 맥락을 공급하는 시스템을 만드는 것이 더 중요하다. 신입사원 비유: 아무리 똑똑해도 온보딩 없이는 무능하다
- **도구는 설계 철학을 이해하고 써야 한다** — Slack의 채널/스레드 구조, Notion의 블록 DB 구조, Linear의 사이클 개념 등은 각각 AI와의 연동 효율을 결정하는 핵심 설계 원칙이다
- **MCP는 표준화 레이어, 스킬은 커스터마이징 레이어** — 빠른 시작은 MCP, 실무 최적화는 스킬(API 스크립트)로 가는 것이 현실적인 접근법
- **병렬 에이전트 + 컨텍스트 사전 수집 = AI 생산성의 핵심 패턴** — 여러 데이터 소스를 병렬로 읽어온 뒤 AI에게 넘기면 슬롭(sloppy output) 없이 고품질 결과를 얻을 수 있다
- **스킬의 자기개선 루프** — 스킬 실행 중 에러 발생 시 '이 에러 부분 스킬 업데이트해줘'라고 말하면 Claude가 스킬 파일을 수정하고 즉시 재사용 가능. MCP는 이 루프가 불가능

### 적용 가능한 점

- **Context Sync 패턴**: `/컨텍스트싱크` 명령 하나로 Slack 채널 + Notion 문서 + Google Calendar + Gmail을 병렬 수집하여 오늘의 업무 브리핑 문서를 자동 생성
- **Fireflies API 스킬 연결**: 과거 모든 미팅 내용을 자산화하여 Claude가 히스토리 기반 작업 수행 가능
- **toolSearch: true 설정**: MCP 다수 연결 시 발생하는 컨텍스트 낭비를 해결 (settings.json에 추가)
- **플러그인 → 로컬 스킬 마이그레이션**: 공식 플러그인 설치 후 "이 플러그인을 내 로컬 스킬로 복사해와"라고 요청하면 커스터마이징 가능한 스킬 파일 생성
- **파트너별 CLAUDE.md 관리**: 중요 협업 파트너와의 맥락을 해당 프로젝트 폴더의 CLAUDE.md에 녹여두면 Claude가 자동으로 커뮤니케이션에 활용

### 2. 업무 도구 설계 철학 [00:10:57 - 00:45:48]
**장원준**

주요 B2B SaaS 도구들이 어떤 문제를 해결하기 위해 만들어졌는지, 내부 KPI는 무엇인지를 분석한다.

| 도구 | 설계 철학 | 내부 KPI / 핵심 |
|------|-----------|-----------------|
| **Slack** | 채널 중심 공개 커뮤니케이션 | 팀 2,000개 메시지 누적 시 93% 리텐션 |
| **Gmail** | 검색 중심 외부 커뮤니케이션 | 라벨 시스템이 당시 혁신, 외부 소통의 구조화된 데이터 소스 |
| **Notion** | 블록 단위 구조화 → AI 파싱에 유리 | DB 생성 횟수와 뷰 수 |
| **Airtable** | 구조화된 데이터 허브 (스프레드시트 + 관계형 DB) | Notion은 자연어 허브, Airtable은 데이터 허브 |
| **Linear** | 스프린트 대신 사이클(Cycle) — AI 시대 빠른 개발 속도에 적합 | Jira와 달리 단순화된 구조 |
| **Google Calendar** | 일정 생성 허들 낮추기 | 시간이라는 차원을 구조화 |
| **Fireflies** | API 개방성 극대화 — 팀 전체 미팅 자산화 | 한국어 인식 오류도 AI 후처리로 보완 |

### 3. MCP 딥다이브 — 개념 및 이론 [00:54:51 - 01:07:45]
**정구봉**

MCP를 HTTP와 같은 표준 프로토콜로 이해하는 프레임을 제시한다.

- MCP = AI가 여러 SaaS의 데이터를 표준화된 방식으로 가져오는 프로토콜, USB-C/HTTP처럼 이해
- Anthropic이 만들었고 현재 Linux Foundation으로 관리 이전 중
- Tool / Resource / Prompt 세 가지 기능이 있으나 실제로는 **Tool만 주로 사용**
- **toolSearch** 설정으로 미사용 MCP의 컨텍스트 토큰 소비를 차단 가능
- MCP 연결 스코프: 로컬(홈디렉토리) / 프로젝트(팀 공유 .mcp.json) / 유저(전역)

### 4. MCP 실습 — Notion MCP 연결 및 Linear 플러그인 [01:07:45 - 01:48:54]
**정구봉**

라이브 시연으로 Notion MCP 연결, Linear 플러그인 설치를 진행한다.

- Notion MCP 연결: `claude mcp add --transport http --name notion https://mcp.notion.com/mcp` 후 브라우저 OAuth 인증
- MCP 툴 동작 시 Claude는 노션서치(ID 검색) → 패치(확인) → 업데이트의 순차적 스텝을 자동 수행
- `/mcp` 명령으로 현재 연결된 MCP 목록 확인, `/mcp 서버명 뷰툴즈`로 사용 가능한 툴 목록 확인
- 플러그인은 스킬·에이전트·커맨드·MCP 서버의 패키지 묶음이며 `/plugin`으로 설치·관리
- Claude AI 웹 서비스 장애로 Slack MCP 시연은 차질 발생

### 5. Context Sync 스킬 — MCP vs 스킬 비교 및 워크플로우 [01:48:54 - 02:05:20]
**정구봉**

MCP의 한계와 스킬의 장점을 비교하고, 실제 팀 내 구현한 Context Sync 워크플로우를 공개한다.

- 스킬 = Python/API 스크립트를 Claude Code가 직접 실행 → MCP보다 커스터마이징·에러 핸들링이 자유로움
- **Context Sync** = 8개 서브에이전트를 병렬 실행하여 Slack/Fireflies/Calendar/Gmail/Linear/이전문서/오픈소스/프로젝트 현황을 한 번에 수집
- 수집 → 문서 생성 → PR 생성 → 팀 싱크 미팅 → Fireflies 녹음 → 최종 업데이트 사이클
- "MCP는 Chrome DevTools 정도만 남기고 나머지는 전부 스킬로 교체하는 것이 더 실용적"

### 6. Gmail 스킬 플러그인 실습 [02:05:20 - 02:31:58]
**정구봉**

Gmail+Google Calendar 스킬 플러그인 설치와 Google Cloud OAuth 설정을 라이브로 진행한다.

- Gmail 스킬: Python + uv 가상환경 + Gmail API → 파일 첨부 포함 발송·수신 목록 조회·내용 확인
- Google Cloud Console 설정 순서:
  1. 프로젝트 생성
  2. Gmail API 라이브러리 활성화
  3. OAuth 동의화면 (External)
  4. 스코프 추가
  5. 테스트 유저 등록
  6. OAuth 클라이언트 ID 발급
- 회사 Google Workspace는 관리자 권한 없으면 제한 → Claude에게 권한 요청 문구를 작성시켜 Slack MCP로 개발자에게 전송하는 방식으로 우회
- 데이터 저장 전략: 로컬 MD 파일이 DB와 기능적으로 동일 → "리드를 많이 해야 좋은 라이트가 나온다"
