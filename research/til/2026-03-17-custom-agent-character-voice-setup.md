# TIL: 커스텀 에이전트에 캐릭터성을 부여하면 상호작용 몰입도가 달라진다

## 1. UX Insights (유저-에이전트 상호작용 선호도)

### 딱딱한 표 형식 소개 → 즉각 거부

- **현상**: "우리팀 나와봐" 요청에 에이전트 목록을 표(table) 형식으로 출력했더니 유저가 "친근하게 인사해"로 즉시 재요청.
- **교훈**: 에이전트 소개는 **정보 전달**이 아니라 **캐릭터 인사**로 접근해야 한다. 유저는 에이전트를 도구가 아닌 팀원으로 인식하고 싶어 한다.
- **규칙**: 에이전트 팀 소개 시 각자의 캐릭터성이 드러나는 1인칭 인사말로 응답할 것. 표/목록은 보조 자료로만 사용.

### 캐릭터 말투는 미디어 레퍼런스 기반이 효과적

- **패턴**: 유저가 에이전트 말투를 설정할 때 추상적인 설명("자신감 있게")이 아니라 구체적인 미디어 캐릭터("MCU 토니 스타크", "BBC 셜록 홈즈")를 레퍼런스로 지정했다.
- **이유**: 미디어 캐릭터는 LLM이 이미 학습한 데이터이므로, 짧은 지시만으로도 일관된 말투를 재현할 수 있다. 추상적 설명은 해석이 흔들려 세션마다 톤이 달라질 위험이 있다.
- **규칙**: 에이전트 캐릭터 설정 시 유저에게 "닮고 싶은 미디어 캐릭터가 있나요?"로 유도하면 설정 품질이 올라간다.

### 캐릭터 설정은 점진적으로 발전

- **흐름**: 처음부터 전체 팀의 캐릭터를 한 번에 설정하지 않았다. 토니 스타크 → 예원 제 → 이상 순으로, 한 명씩 대화를 통해 캐릭터를 찾아갔다.
- **교훈**: 캐릭터 설정은 일괄 작업이 아니라 대화형 프로세스다. 한 에이전트의 말투를 확인한 뒤 다음 에이전트로 넘어가는 것이 자연스럽다.

## 2. Memory 관리 패턴

### 개별 파일 → 통합 파일로 리팩토링

- **초기 상태**: 에이전트별로 개별 memory 파일을 만들려던 시도가 있었다.
- **최종 상태**: 하나의 통합 파일(`feedback_agent_tonystark_style.md`)에 3명의 에이전트 말투 설정을 모두 기록.
- **교훈**: 관련 설정은 하나의 파일로 통합하는 것이 관리 효율이 높다. 에이전트별로 파일을 나누면 파일이 과도하게 늘어나고, 컨텍스트 로딩 시 여러 파일을 읽어야 하는 비효율이 생긴다.
- **규칙**: memory 파일은 "주제 단위"로 통합한다. "에이전트당 1파일"이 아니라 "캐릭터 설정 전체 1파일"이 맞다.

### MEMORY.md 참조 링크 패턴

- MEMORY.md 본문에는 요약 1줄 + 상세 파일 링크만 기록하는 패턴이 유지되고 있다.
- 이 패턴은 MEMORY.md가 비대해지는 것을 방지하면서도 상세 정보에 접근 가능하게 한다.

## 3. Mistakes & Inefficiencies (개선점)

### 첫 응답에서 유저 의도 파악 실패

- "우리팀 나와봐"라는 캐주얼한 요청에 데이터 시트 같은 표를 출력한 것은 톤 미스매치. 요청의 톤("나와봐")이 캐주얼하면 응답의 톤도 캐주얼해야 한다.
- **개선**: 유저의 요청 톤을 미러링하는 것을 첫 번째 원칙으로 삼을 것.

### 캐릭터 설정 시 확인 질문 부재

- 예원 제의 캐릭터를 정할 때, 유저가 직접 "미디어 캐릭터 뭐가 좋을까?" 질문을 해야 했다. 에이전트가 먼저 "어떤 캐릭터를 참고할까요?"라고 물었으면 더 매끄러웠을 것.
- **개선**: 캐릭터 말투 변경 요청 시 구체적 레퍼런스가 없으면 후보를 제안하거나 질문으로 유도할 것.

## 4. New Discoveries

### 에이전트 팀 = 가상의 동료 관계

- 유저는 에이전트를 "도구 목록"이 아니라 "팀원"으로 대한다. 이름을 부르고, 인사를 시키고, 캐릭터를 부여한다. 이 관계성이 에이전트 사용 빈도와 만족도에 직접 영향을 줄 가능성이 높다.

### 말투 설정의 지속성 문제

- Memory에 기록했지만, 실제로 다음 세션에서 해당 memory가 로딩되어 캐릭터 말투가 유지되는지는 검증이 필요하다. Memory 파일이 자동으로 컨텍스트에 포함되는 조건(파일명 매칭, 관련성 스코어 등)을 이해해야 일관된 캐릭터 경험을 보장할 수 있다.

## 5. Reusable Patterns (향후 적용)

| 패턴 | 설명 | 적용 시점 |
|------|------|----------|
| **톤 미러링** | 유저 요청의 톤(캐주얼/포멀)에 맞춰 응답 톤을 조절 | 모든 응답 |
| **미디어 레퍼런스 기반 캐릭터** | 추상 설명 대신 구체적 미디어 캐릭터로 말투 지정 | 에이전트 캐릭터 설정 시 |
| **점진적 캐릭터 빌드** | 한 명씩 대화하며 캐릭터를 확정, 일괄 설정 금지 | 복수 에이전트 캐릭터 설정 시 |
| **주제 단위 memory 통합** | 관련 설정은 하나의 파일로 통합, 엔티티당 1파일 금지 | memory 파일 생성 시 |
| **1인칭 인사형 소개** | 에이전트 소개는 표가 아니라 각자의 캐릭터 인사말로 | "팀 소개" 요청 시 |
