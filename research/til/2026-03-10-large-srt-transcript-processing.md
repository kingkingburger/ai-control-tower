# TIL: 대용량 SRT 트랜스크립트를 Claude Code로 정리하기

## 1. 기술적 배움

### 대용량 파일 처리 전략

- **SRT 파일 크기 한계**: 11,128줄(~212KB, ~107k tokens)의 SRT 파일은 한 번에 읽을 수 없다. Read 도구의 기본 limit은 2000줄이므로, 전체를 한 번에 로드하려 하면 실패하거나 컨텍스트를 초과한다.
- **부분 읽기(chunked read) 패턴**: `offset`과 `limit` 파라미터를 활용해 SRT 파일을 구간별로 나눠 읽는다. 타임스탬프 기준으로 위치를 파악한 뒤, 필요한 구간만 정밀 읽기하면 토큰 소비를 대폭 줄일 수 있다.
- **Grep으로 타임스탬프 위치 파악**: SRT 파일에서 `00:30:00`, `01:00:00` 같은 주요 시간대를 Grep으로 검색하면 해당 줄 번호를 얻을 수 있다. 이를 기반으로 Read의 offset을 결정하는 것이 효율적이다.

### SRT 파일 특성

- **자동 음성인식(ASR) 오류**: 고유명사가 여러 variant로 나타난다. 예: "클레리파이/클러리파이/클리어리파이"(Clarify), "플레이라이트/Playwright" 등. 수동 보정이 필요하다.
- **SRT 구조**: 4줄 단위(인덱스 / 타임스탬프 / 텍스트 / 빈 줄)로 구성. 타임스탬프 형식은 `HH:MM:SS,mmm --> HH:MM:SS,mmm`. Grep 패턴을 설계할 때 이 구조를 이해하면 검색 효율이 올라간다.

### 분석 JSON의 역할

- 트랜스크립트의 사전 분석 결과(섹션 구분, 화자 식별, 핵심 주제)가 JSON으로 있으면 SRT 전체를 읽지 않아도 핵심 구조를 파악할 수 있다. **분석 JSON이 SRT 원본보다 훨씬 더 가치 있는 입력**이다.
- 패턴: 대용량 원본 + 소량 구조화 메타데이터 조합이 최적. 원본은 참조용, 메타데이터가 작업 드라이버.

## 2. 워크플로우 패턴 (잘 된 것)

### Grep-first 탐색 패턴

1. Grep으로 파일 구조/키워드 위치 파악
2. Read로 필요한 구간만 정밀 읽기
3. 전체 파일을 읽지 않고도 핵심 내용 추출

이 패턴은 **토큰 효율**과 **정확도** 모두에서 우수하다. 특히 SRT처럼 반복 구조(타임스탬프 + 텍스트)가 있는 파일에 최적화되어 있다.

### 구조화된 출력 템플릿

마크다운 정리 문서에 일관된 구조를 적용한 것이 효과적이었다:
- frontmatter(메타데이터) -> 요약 -> 인사이트 -> 세션별 상세 -> 타임스탬프 발언 -> 도구/개념 정리
- 이 구조는 다른 일차별 문서(1, 2, 4일차)에도 재사용 가능하다.

### 화자 식별 + 고유명사 보정

- ASR이 화자를 구분하지 못하므로, 문맥에서 화자를 추론해야 한다. 세션 구성(누가 어느 파트를 담당)을 먼저 파악하면 화자 식별이 쉬워진다.
- 고유명사 variant를 통일하는 작업은 Grep으로 variant를 먼저 수집한 뒤 일괄 치환하는 것이 효율적이다.

## 3. 실수와 비효율 (개선점)

### 전체 파일 읽기 시도

- 처음에 SRT 파일을 한 번에 읽으려 시도하면 토큰 한계에 부딪힌다. **대용량 파일은 항상 크기부터 확인**(`wc -l` 또는 파일 크기 확인)하고, 전략을 세운 뒤 접근해야 한다.
- 경험 법칙: 5,000줄 이상이면 분할 읽기, 2,000줄 이하면 전체 읽기.

### 분석 JSON 선처리 누락

- SRT보다 분석 JSON을 먼저 읽었으면 SRT를 읽는 범위를 더 좁힐 수 있었다. 구조화된 메타데이터가 있다면 **항상 메타데이터부터 읽는다**.

### 트랜스크립트 발언 추출의 한계

- SRT에서 "핵심 발언"을 추출할 때, 자동 음성인식 텍스트는 문장 경계가 불명확하다. 한 발언이 여러 SRT 블록에 걸쳐 있을 수 있다. 타임스탬프 기준으로 앞뒤 블록을 함께 읽어야 완전한 발언을 얻을 수 있다.

## 4. 재사용 가능한 패턴 (향후 적용)

| 패턴 | 설명 | 적용 시점 |
|------|------|----------|
| **크기 우선 확인** | 파일 크기/줄 수 먼저 확인 후 전략 결정 | 모든 대용량 파일 처리 |
| **Grep 후 Read** | 검색으로 위치 파악 후 부분 읽기 | SRT, 로그, CSV 등 구조화된 대용량 파일 |
| **메타데이터 우선 확인** | 분석 JSON/요약 먼저 읽고 원본은 참조용 | 사전 분석이 존재하는 경우 |
| **템플릿 재사용** | 동일 시리즈 문서는 첫 번째 결과물을 템플릿으로 | 시리즈 강의, 반복 보고서 |
| **ASR 보정 워크플로우** | Grep으로 variant 수집 -> 정규화 매핑 -> 일괄 치환 | 음성인식 기반 텍스트 처리 |
