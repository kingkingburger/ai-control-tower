# 2026-05-19 — 증거 남기기 실행 규칙

> 결론: 쉬기 전에 증거 1개를 남긴다. 증거가 있으면 휴식이고, 없으면 회피다.

## 문제

생각할 것과 도전할 것이 많은데도, 어느 순간 "이 정도면 됐겠지"라고 판단하고
유튜브 같은 즉각 보상으로 빠진다.

이 판단은 실제로 일이 끝났다는 근거가 있어서가 아니라, 불확실한 과제를 회피
가능한 과제로 재분류하는 신호에 가깝다.

특징:

- 끝이 애매하다.
- 잘했는지 바로 보이지 않는다.
- 시작하면 부족한 부분이 드러난다.
- 보상이 늦게 온다.
- 실패하면 기분이 상한다.

그래서 앞으로 종료 판단은 기분이 아니라 증거로 한다.

## 핵심 규칙

> 쉬기 전에 증거 1개.

증거는 거창한 결과물이 아니어도 된다. 내일의 내가 이어받을 수 있게 남은 흔적이면
충분하다.

예시:

- 테스트 실패 원인: `getOracleConnection` mock 누락.
- LeetCode: 투포인터로 풀 것 같음. 정렬 필요 여부 확인.
- 인수인계: Oracle 브랜치는 Repository 경계 전환 중, 다음은 audit/license.
- 내일 첫 작업: `bun run test` 실패 1개 줄이기.

## 유튜브 보기 전 게이트

유튜브나 즉각 보상으로 넘어가기 전에 3개만 확인한다.

1. 내가 방금 뭘 하려고 했지?
2. 그걸 했다는 흔적이 어디 있지?
3. 내일 내가 이어받을 수 있나?

3번이 "아니오"면 아직 종료가 아니다. 그때 3~5줄만 남긴다.

## 증거 템플릿

```md
오늘 남긴 증거:
- 한 일:
- 알게 된 것:
- 다음 첫 행동:
```

예시:

```md
오늘 남긴 증거:
- 한 일: Octoto Oracle 브랜치 테스트 실패를 확인했다.
- 알게 된 것: 일부 테스트 mock이 새 DB export를 따라가지 못한다.
- 다음 첫 행동: `getOracleConnection: undefined` mock 추가 후 테스트 1개 재실행.
```

## 업무용 질문

업무에서 할 일을 못 찾을 때는 새 일을 발명하려 하지 않는다. 다음 질문으로 시작한다.

> 내가 갑자기 빠져도 이 작업을 이어받을 수 있게 하려면 무엇을 남겨야 하지?

이 질문으로 나온 일은 실제 업무다.

남길 것:

- 지금 브랜치 목적
- 어디까지 됐는지
- 아직 깨지는 것
- 다음 사람이 먼저 볼 파일
- 절대 건드리면 안 되는 전제

## 내일 후보

- Octoto Oracle 브랜치가 공유 가능한 상태가 아닌 이유 1개 줄이기.
- `bun run test` 실패 원인 1개 줄이기.
- `getOracleConnection` export/mock 불일치 정리.
- LeetCode 1문제는 풀기보다 문제 읽고 접근법 3줄 남기기까지도 성공으로 본다.

## 판단 기준

나쁜 질문:

> 이 정도면 됐나?

좋은 질문:

> 오늘 끝났다고 말하려면 증거가 뭐지?

판단력은 많이 생각해서 생기는 것이 아니라, 종료 전에 증거를 남기는 반복으로
생긴다.
