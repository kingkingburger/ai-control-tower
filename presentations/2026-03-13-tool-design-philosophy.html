AI Native Camp 2기 · Day 2

도구에는 설계철학이 있다.
AI는 그 구조를 읽는다.

업무 도구의 설계 원칙을 이해하면, AI 활용의 차원이 달라진다

장원준 2026.03.02
01
PREMISE

AI에게 필요한 것은
맥락(Context)이다

"아무리 똑똒하고 학벌 좋아도, 온보딩 없이는 바보다 — AI도 마찬가지"

PREMISE

AI = 똑똑한 신입사원

🚫

맥락 없는 AI

  • 뭘 해야 하는지 모른다
  • 회사 상황을 모른다
  • 도구를 어떻게 써야 하는지 모른다
  • 결과물 = 슬롭(Slop)
✅

맥락 있는 AI

  • 업무 흐름을 이해한다
  • 도구의 구조를 파악한다
  • 데이터를 정확하게 읽어온다
  • 결과물 = 고품질 아웃풋
CORE IDEA

방식이 바뀌면 도구를 잘 쓰게 되는 것이고,
AI한테 필요한 맥락을 이해하게 만드는 것이 본질이다

02
DESIGN PHILOSOPHY

뻔한 시장에서 큰 획을 그은 서비스는
다 잘된 이유가 있다

그 이유를 알고 AI에게 커뮤니케이션해야 성능이 극대화된다

TOOL 1

Slack — 채널 중심 공개 커뮤니케이션

💬

설계 철학

  • 이메일의 Push 중심에서 Pull 중심으로
  • 소통의 헤게모니를 바꾼 패러다임 전환
  • 채널 + 스레드 구조 = AI가 맥락을 추적하기 좋은 구조
  • AI 시대에도 무조건 살아남을 소프트웨어

내부 KPI

93%

리텐션

팀이 누적 2,000개 이상 메시지를 보내면
93%가 계속 사용한다

TOOL 2

Gmail — 검색 중심 외부 커뮤니케이션

📧

설계 철학

  • Outlook의 폴더링/자동화 중심에서 벗어남
  • "우리는 그냥 검색하면 된다"로 큰 히트
  • 라벨 시스템이 당시 혁신
  • 외부 소통의 구조화된 데이터 소스
🤖

AI 관점에서의 가치

  • 외부 커뮤니케이션 이력 = 귀중한 맥락 데이터
  • 검색 기반 구조 → AI가 필요한 정보를 빠르게 탐색
  • 라벨/필터 = AI에게 분류 힌트 제공
  • MCP 또는 API 스킬로 연결 가능
TOOL 3

Notion — 블록 단위 구조화

📝

설계 철학

  • 모든 것을 블록 단위로 구조화
  • 블록 구조 = AI 파싱에 매우 유리
  • Notion은 자연어 허브
  • (cf. Airtable은 데이터 허브)

히어로 KPI

🏆

DB 생성 횟수 & 뷰 수

조직 내에서 DB를 많이 만들고
뷰를 많이 만드는 사람이 히어로

TOOL 4

Airtable — 구조화된 데이터 허브

📊

설계 철학

  • 스프레드시트 + 관계형 DB의 결합
  • 비개발자도 구조화된 데이터를 다룰 수 있게
  • API 친화적 설계 → 자동화에 강점
↔

Notion vs Airtable

NotionAirtable

강점문서 + DB 통합정형 데이터 관리

TOOL 5

Linear — 스프린트를 넘어선 사이클

🔄

설계 철학

  • Jira의 스프린트를 정면으로 부정
  • 스프린트 대신 '사이클(Cycle)' 개념 도입
  • "2주라는 인위적 시간에 맞추는 게 아니라
    각자의 리듬에 맞춰야 한다"
  • AI 시대의 빠른 개발 속도에 적합한 단순화된 구조
⚖

Jira vs Linear

JiraLinear

AI 시대무거운 설정 부담빠른 반복에 적합
TOOL 6&7

Calendar & Fireflies

📅

Google Calendar

  • 일정 생성의 허들을 극도로 낮춤
  • 시간이라는 차원을 구조화
  • AI에게 "언제"라는 맥락을 제공하는 핵심 소스
🎙

Fireflies

  • 핵심 = API 개방성 극대화
  • 데이터를 서비스 안에 가두지 않는 철학
  • 팀 전체 미팅을 자산화
  • 한국어 인식 오류도 AI 후처리로 보완 가능

"Fireflies를 쓰게 된 이유는 API 때문입니다. 데이터를 서비스 안에서만 쓰게 하는 곳이 많은데, Fireflies는 제한이 별로 없어요."

— 장원준

INSIGHT

Claude Code가 도구를 잠식하고 있다

🔌

MCP & 스킬로 연결

⬇
MCP / API 스킬
표준 연결 레이어
⬇
Claude Code
맥락을 이해하고 실행하는 AI
💡

도구를 남길 것인가, 말 것인가

"Claude Code를 전면적으로 쓰기로 결정하면서, 이 툴들을 남겨야 돼 말아야 돼를 회의했는데 —"

확실히 Claude Code가 훨씬 많은 서비스들을 잠식한 것 같아요.

하지만 각 도구의 설계 철학을 이해해야
AI가 그 구조를 제대로 읽을 수 있다

Takeaways

  • 01 모든 성공한 B2B SaaS에는 고유한 설계 철학이 있다.
    그 철학이 데이터의 구조를 결정한다.
  • 02 AI는 그 구조를 읽는다.
    설계 철학을 이해하면, AI에게 더 정확한 맥락을 공급할 수 있다.
  • 03 AI 네이티브 업무의 본질은 맥락 공급 구조 설계다.
    똑똑한 AI보다, 올바른 맥락을 공급하는 시스템이 더 중요하다.
  • 04 도구의 철학을 알고 → AI에게 커뮤니케이션하면 → 성능이 극대화된다.
