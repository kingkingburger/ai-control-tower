## 목표 (Goal)

Octopus Simulation Engine v3(Composable Component Architecture)를 기반으로, 삼성중공업 거제조선소의 **블록 건조 공정에 대한 Capacity Planning Simulation**을 구현한다.

삼성중공업이 현재 애니로직(AnyLogic) + JavaScript + Excel + Python으로 수행하는 검증 프로세스를, Octopus Simulator 단일 플랫폼으로 대체하는 것이 최종 목표다.

---

## 핵심 엔티티 (Ontology)

| 용어 | 시뮬레이션 개념 | 설명 |
|------|----------------|------|
| **블록(Block)** | Entity / Prefab | 선박을 구성하는 단위. 크기, 무게, 공정경로 속성을 가짐 |
| **공정(Process)** | Processor / Station | 중조, 선행의장, 대조, 선행도장, 탑재 등 작업 단계 |
| **공정경로(Route)** | Routing Rule | 블록 종류에 따라 거쳐야 할 공정 순서. 일부 건너뛸 수 있음 |
| **합체(Merge)** | Entity Merge | 여러 블록이 하나의 새 블록으로 합쳐짐 (A+B+C→D) |
| **택트타임(Tact Time)** | Processing Time | 공정별 블록 처리 시간. Merge 후 새 Prefab 기준으로 자동 적용 |
| **배치면적(Floor Area)** | Spatial Capacity | 공정 내 블록이 차지하는 물리적 공간. 면적 초과 시 대기 발생 |
| **용접장(Welding Bay)** | Resource | 동시 작업 가능한 용접 장비/인력 수 |
| **Lot 추적** | Entity Lineage | Merge된 블록이 어떤 부품들로 구성되었는지 이력 기록 |

## 삼성중공업 요구사항 (출처: 최재호 이메일 2026-03-03)

### 1. Process — 공정별 라우팅 분기

- Capacity 검증 시 주요 공정으로 구분되며, 제품 기준 프로세스 간 연결관계가 다양하게 구성됨
- **중조→선행의장→대조→선행도장→탑재** 모두 거쳐갈 수도, 일부 건너뛸 수도 있음
- 각 공정별 리소스 제약:
  - 동시 제작 블록 개수
  - 용접장 능력
  - 배치 면적

### 2. Product — Entity 조합 및 ID 변환

- 초기 Source에서 생성된 제품 ID가 끝까지 유지되지 않음
- 여러 개가 모여 하나의 블록으로 합쳐짐: **A,B,C → A** 또는 **A,B,C → D**
- 제품 변화에 따라 제품 생성 및 Destroy
- 변경된 제품 ID에 따라 택트타임 및 리소스 제약 설정 로직

### 3. 디지털트윈 연동

- 온라인 모드: DT 실 데이터를 활용한 시뮬레이션
- 오프라인 모드: What-if Analysis 수행
- 시뮬레이션 결과를 DT 플랫폼에서 시각화

## 마일스톤 및 수용 기준 (Acceptance Criteria)

### M1: 전체 기능 기본형 데모 (4월 말)

**시나리오:**
1. 블록 3종(소형/중형/대형) Source에서 생성
2. 종류별 다른 공정경로로 라우팅 분기
   - 소형: 중조 → 대조 → 탑재 (의장/도장 건너뜀)
   - 중형: 중조 → 선행의장 → 대조 → 탑재
   - 대형: 중조 → 선행의장 → 대조 → 선행도장 → 탑재 (전체)
3. 중조 공정에서 소형 3개가 1개 중형으로 Merge (A+B+C → D)
4. Merge 후 새 Prefab의 택트타임 자동 적용
5. 배치 면적 제약으로 동시 작업 수 제한 → 대기 발생
6. KPI 리포트: 처리량, 대기시간, 공정별 활용률

**수용 기준:**
- [ ] 3종 블록이 Prefab별 다른 경로를 정상적으로 따름
- [ ] Entity Merge 후 새 ID 생성 및 이전 Entity Destroy
- [ ] Merge된 Entity에서 원래 부품 Lot 추적 가능
- [ ] 배치 면적 초과 시 대기(Queue) 발생
- [ ] 시뮬레이션 완료 후 KPI 통계 출력

### M2: 고도화 (5월)

- 실제 삼성중공업 블록 데이터(10종+)로 실규모 시뮬레이션
- 용접장 능력, 인력 자원 제약 반영
- 시나리오/실험계획/최적화 3모드 지원
- 디지털트윈 연동 API 설계

### M3: 비교 검증 (5월~)

- 서경민 CTO NSL 연구실의 Simio/DEVS 결과와 비교
- 동일 시나리오에서 처리량, 대기시간 등 주요 지표 비교
- 학부생 2명(Simio 비교) + 석사 3명(DEVS 비교) 투입 예정

## 시뮬레이션 기초 개념 참고

### DES (Discrete Event Simulation)
이산 사건 시뮬레이션. 시간이 연속이 아닌 "이벤트 발생 시점"으로 진행. 조선소 공정처럼 블록이 공정에 도착/출발하는 이벤트 기반 모델링에 적합.

### DEVS (Discrete Event System Specification)
DES의 수학적 형식론. 시스템을 atomic model(단일 공정)과 coupled model(공정들의 연결)로 계층적으로 구성. 서경민 CTO 팀이 비교 검증에 사용할 방법론.

### Capacity Planning Simulation
주어진 자원(공간, 장비, 인력) 제약 하에서 생산 능력을 평가. "이 공장 레이아웃으로 월 몇 개 블록을 처리할 수 있는가?" 질문에 답하는 시뮬레이션.

### Entity 생명주기
Source(생성) → Process(가공) → Merge(합체)/Split(분리) → Sink(완료). 조선소에서는 블록이 합쳐지는 Merge가 핵심.

### Resource Constraint
공정에서 동시에 사용할 수 있는 자원의 한계. 용접장 2개면 동시에 2블록만 작업 가능, 나머지는 대기.

### What-if Analysis
"설비를 1개 추가하면?", "야간 작업을 도입하면?" 등 가상 시나리오를 시뮬레이션하여 결과를 비교하는 의사결정 지원.
