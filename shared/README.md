# Shared

이 디렉터리는 여러 프로젝트 팀이 공유하는 에이전트 역할, 규칙, 템플릿, 스킬을 보관한다.
프로젝트별 맥락과 실행 메모리는 `projects/<project>/`에 두고, 여기에는 반복
가능한 공통 자산만 둔다.

## 목적

- 재사용 가능한 에이전트 규칙, 템플릿, 워크플로를 한곳에 둔다.
- 프로젝트별 팀이 같은 규칙을 복사하지 않고 참조하게 한다.
- 반복 실행에서 검증된 규칙만 프로젝트 문서나 공통 자산으로 승격한다.

## 구조

- `agents/`: 여러 프로젝트 팀이 참조하는 공통 에이전트 역할.
- `harnesses/`: 여러 작업 표면에서 재사용하는 팀 운영 하네스와 manifest.
- `rules/`: 재사용 가능한 작업 규칙과 운영 정책.
  - `work-style.md`: 언어와 프레임워크에 종속되지 않는 사용자 작업 스타일과
    에이전트 운영 기본값.
- `templates/`: 프로젝트 문서 템플릿.
- `skills/project-team/`: 프로젝트 팀 프로필과 shared 규칙을 적용하는 Codex 스킬.
- `skills/deep-goal-council/`: Deep Goal Council 하네스를 실행하는 스킬 어댑터.

## 언어

프로젝트 팀 문서, 세션 메모리, 증강 후보는 기본적으로 한국어로
작성한다. 코드, 명령어, 경로, 환경 변수, API 이름, 외부 고유명사는 원문을
유지한다.

## 경계

대상 저장소에는 협업자가 봐도 되는 규칙만 둔다.

- 빌드와 테스트 명령
- 아키텍처와 계층 규칙
- 커밋과 검증 요구사항
- 금지 파일과 안전 경계

프로젝트별 맥락은 `projects/<project>/`에 둔다.

- 반복되는 에이전트 실수
- 세션 메모리
- 프로젝트 전략 메모
- 아직 대상 저장소 문서로 올리기 이른 규칙 후보

## 승격 규칙

1. 1회성 관찰은 프로젝트 `session-memory.md`에 기록한다.
2. 2회 이상 반복되면 `agent-rules-candidates.md`로 올린다.
3. 협업자에게도 유익하면 대상 저장소의 `AGENTS.md`나 docs로 승격한다.
4. 여러 프로젝트에 반복 적용되면 `shared/rules/`, `shared/templates/`,
   `shared/skills/`로 승격한다.

## 세션 종료 메모리

세션 종료 때마다 관련 프로젝트 프로필에 배운 점과 증강할 점을 반드시
추가한다. 이 누적 메모리가 하네스의 복리 계층이다.

## 프로젝트 메모리와 Shared 승격

프로젝트별 히스토리와 학습은 각 프로젝트 안의 명시된 메모리 문서에 누적한다.
`ai-control-tower`는 그 원시 히스토리를 대신 저장하는 곳이 아니라, 반복되는 운영
규칙을 shared 규칙, 템플릿, 스킬로 승격하는 곳이다.

`.omc/project-memory.json` 같은 도구 종속 상태 파일은 지속 메모리 원본으로 쓰지
않는다. 유효한 내용은 프로젝트 메모리로 이관하고, 반복 규칙만 `shared/`로
승격한다.
