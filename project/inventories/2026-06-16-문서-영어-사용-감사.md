# 문서 영어 사용 감사

작성일: 2026-06-16

## 결론

이 저장소의 영어 문서는 특정 시점에 의도적으로 "영어로 전환"한 결과라기보다,
외부 도구 템플릿과 AI 생성 산출물이 들어오면서 누적된 것이다. 루트 지침은
한국어 답변과 한국어 문서화를 선호하지만, 초기 커밋부터 커밋 메시지와 일부
문서 제목은 영어 관습을 그대로 사용했다.

## 왜 생겼나

1. **도구 원본 유입**
   - `.claude/skills/` 문서는 Claude Code 스킬 원본과 참고 문서를 그대로
     복사한 형태라 영어 설명이 많았다.
2. **AI 생성 템플릿 기본값**
   - roadmap, checklist, daily-report, TIL 문서가 영어 섹션명 중심 템플릿으로
     생성됐다.
3. **기술 용어와 자연어의 경계 미분리**
   - `API`, `GitHub`, `OAuth`, `AlarmRule`, `active`처럼 유지해야 하는
     식별자와 `Executive Summary`, `Current State`처럼 번역해야 하는 문장형
     제목이 같은 기준으로 방치됐다.
4. **한국어 문서 규칙의 검사 부재**
   - "한국어로 답변한다"는 지침은 있었지만, 문서에 남는 영어 제목과 문장을
     자동으로 잡는 검증은 없었다.

## 이번 정리 기준

- 한글로 바꿀 것
  - 문서 제목, 섹션 제목, 설명문, 체크리스트 설명, 보고서 항목명, 스킬 사용법
    문장.
- 그대로 둘 것
  - 코드 식별자, 파일 경로, 명령어, 환경 변수, URL, 브랜치명, 제품명,
    프로토콜명, API 이름, 인용된 외부 고유명사.
- 판단이 애매한 것
  - 한국어 문장 안의 영어 기술어는 유지하되, 영어-only 제목이나 설명문이면
    한국어 설명을 붙이거나 제목 자체를 한국어로 바꾼다.

## 재발 방지

- 문서 추가 후 `.omo/ulw-loop/check-doc-korean.py` 같은 스캔으로 영어-only
  제목과 설명문 후보를 확인한다.
- 새 메모리 노트와 세션 종료 요약은 한국어로 작성한다.
- 외부 스킬 원본을 들여올 때도 사람이 읽는 설명문은 한국어로 로컬화하고,
  실행에 필요한 식별자만 원문으로 유지한다.
