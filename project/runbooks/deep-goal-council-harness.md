# 깊은 목표 협의회 하네스

깊은 목표와 방향을 잡기 위한 경쟁형 에이전트 팀 하네스다. 목표를 작게 잡는 습관을 보정하기 위해 여러 팀이 같은 현재 상태를 서로 다른 철학으로 해석하고, 사용자가 최종 심사자가 된다.

## 목적

이 하네스는 단기 할 일 목록을 만드는 도구가 아니다. 현재 상태를 기반으로 더 큰 시간 지평, 정체성 변화, 실행 가능한 첫 증거를 함께 제안한다.

## 저장 위치

- 하네스 manifest: `shared/harnesses/deep-goal-council/README.md`
- 실행 스킬: `shared/skills/deep-goal-council/SKILL.md`
- 역할 구조: `shared/skills/deep-goal-council/references/team-blueprints.md`
- 출력 계약: `shared/skills/deep-goal-council/references/output-contract.md`
- 표면별 변환: `shared/skills/deep-goal-council/references/surface-adapters.md`
- 실행 산출물: `_workspace/deep-goal-council/{YYYY-MM-DD}-{slug}/`

## 스킬과 하네스의 관계

`shared/skills/deep-goal-council/SKILL.md`는 하네스 자체가 아니라 실행 어댑터다. 하네스의 본체는 manifest, 역할 구조, 출력 계약, 표면별 어댑터, 운영 런북이며, 스킬은 에이전트 런타임이 이 하네스를 일관되게 호출하도록 연결한다.

## 운영 흐름

1. 사용자의 현재 상태와 고민을 받는다.
2. 작업 표면을 분류한다: 상담, 공부, 개발, 디자인, 운영, 커리어/인생, general.
3. Situation Brief를 만든다.
4. 3-5개 경쟁 팀을 구성한다.
5. 각 팀이 내부 비판 후 제안서를 낸다.
6. 팀 간 교차 비판을 수행한다.
7. 사용자가 심사할 Judge Packet을 만든다.
8. 사용자가 선택하면 선택안을 7일 실험과 12주 캠페인으로 변환한다.

## 기본 팀

| 팀 | 역할 |
| --- | --- |
| moonshot-team | 목표를 의도적으로 크게 잡고 10배 방향을 제안한다. |
| compound-team | 누적 가능한 루틴과 시스템을 설계한다. |
| constraint-breaker-team | 병목과 작업 형식을 바꾼다. |
| craft-team | 실력, 품질, 정체성 변화를 중심에 둔다. |
| operator-team | 이번 7일 안에 관찰 가능한 증거를 만든다. |

## 심사 기준

| 기준 | 질문 |
| --- | --- |
| 깊이 | 단기 할 일이 아니라 방향과 정체성을 바꾸는가? |
| 야심 | 지금의 기본 목표보다 충분히 큰가? |
| 현실성 | 현재 제약을 무시하지 않는가? |
| 증거 가능성 | 7일 안에 관찰 가능한 산출물이 있는가? |
| 회수 가능성 | 틀렸을 때 빠져나올 방법이 있는가? |
| 표면 적합성 | 상담/공부/개발/디자인 등 실제 사용 맥락에 맞는가? |

## 첫 실행 프롬프트

```text
현재 상태를 바탕으로 Deep Goal Council을 실행해줘.
내 목표가 너무 단기적이고 작아지는 패턴을 보정하고 싶어.
상담/공부/개발/디자인에도 재사용할 수 있게, 여러 경쟁 팀이 제안서를 내고 내가 심사할 수 있는 Judge Packet으로 정리해줘.
```

## 운영 원칙

- 사용자가 최종 심사자다. 에이전트는 판단을 돕되 선택을 대체하지 않는다.
- 각 팀은 다른 팀과 충분히 다른 철학을 가져야 한다.
- 모든 큰 목표는 12주 캠페인과 7일 첫 증거로 내려와야 한다.
- 모든 현실적 계획은 1년 이상 방향과 연결되어야 한다.
- 감시자는 팀 안에서 가장 불편한 반론을 맡는다.
- 상담/정신건강 표면에서는 안전을 먼저 두고, 진단이나 치료를 대체하지 않는다.

## 갱신 규칙

반복 실행 후 다음 신호가 2회 이상 나오면 스킬을 갱신한다.

- 제안들이 서로 비슷해서 경쟁 효과가 약하다.
- 목표가 다시 7일 할 일로만 축소된다.
- 사용자가 심사하기 어렵다고 느낀다.
- 특정 표면, 예를 들어 공부나 디자인에서 산출물 형식이 부족하다.
- 감시자 비판이 형식적이다.
